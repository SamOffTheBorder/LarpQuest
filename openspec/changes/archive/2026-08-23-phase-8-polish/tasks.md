Note (also corrected in `specs/share-links/spec.md`): a signed URL is a self-contained credential — revocation stops `resolveShareLink` from returning a story id (so no *new* URL can be issued), but cannot invalidate a URL already handed to a browser before revocation; the short TTL is what bounds that exposure window, not the revocation itself. The original task wording ("stops access immediately including previously-issued signed URLs") overstated what's achievable with bearer-token signed URLs and was corrected rather than implemented as literally described.
